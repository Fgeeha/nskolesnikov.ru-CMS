# Управление содержимым

Как редактировать сайт без изменения кода.

## Два интерфейса

| Интерфейс | Что редактируется |
|-----------|-------------------|
| django CMS (`/`, режим редактирования) | структура страниц и состав блоков |
| Django Admin (`/admin/`) | данные: проекты, навыки, статьи, опыт, ссылки |

Правило простое: **что** показывать — в админке, **где и в каком порядке** — в
CMS.

## Вход

1. Откройте `/admin/` и войдите под своей учётной записью.
2. Вернитесь на сайт — сверху появится панель django CMS.

## Страницы и режимы

Панель CMS переключает три режима:

- **Preview** — как видит посетитель;
- **Content** — правка текста прямо на странице;
- **Structure** — дерево блоков: добавление, перемещение, удаление.

Изменения сохраняются как черновик. Пока черновик не опубликован, посетители
видят предыдущую версию. Публикация — кнопка в панели CMS.

### Шаблоны страниц

| Шаблон | Плейсхолдеры | Когда использовать |
|--------|--------------|--------------------|
| Главная страница | `hero`, `sections`, `closing` | только для главной |
| Обычная страница | `content`, `sections` | текстовые страницы с заголовком |
| Страница без боковых отступов | `content` | нестандартная вёрстка из блоков |

Шаблон выбирается при создании страницы и меняется в её свойствах.

### Создание страницы

1. Панель CMS → **Страница** → **Создать страницу**.
2. Заполните заголовок, slug и описание для поисковых систем.
3. Выберите шаблон.
4. Перейдите в режим **Structure** и добавьте блоки.
5. Опубликуйте.

Главная страница отмечается как домашняя в списке страниц админки CMS.

## Блоки главной страницы

Все блоки берут данные из моделей: в самом блоке хранятся только параметры
показа. Добавили проект в админке и отметили его избранным — он появится в
блоке «Избранные проекты» без правки страницы.

| Блок | Источник данных | Основные настройки |
|------|-----------------|--------------------|
| Hero | профиль разработчика | заголовок, подзаголовок, текст, две кнопки, терминал |
| Обо мне | профиль разработчика | источник текста (краткий или расширенный), фото, блок фактов |
| Категории навыков | навыки по категориям | выбор категорий (пусто — все) |
| Сетка избранных навыков | навыки с отметкой «показывать на главной» | лимит, показывать уровень |
| Избранные проекты | опубликованные проекты | категория, лимит, только избранные, ссылка на каталог |
| Мини-проекты | активные мини-проекты | лимит, ссылка на каталог |
| Опыт работы | записи опыта | лимит, показывать технологии |
| Образование | записи образования | лимит, показывать сертификаты |
| Социальные ссылки | видимые ссылки | оформление: иконки или карточки |
| Последние статьи | опубликованные статьи | категория, лимит, ссылка на все статьи |
| Призыв к действию | собственный текст | заголовок, текст, две кнопки |
| Контактный блок | профиль и ссылки | текст, показывать форму, ссылки, email |

У каждого блока есть поля **заголовок**, **подзаголовок** и **якорь**. Якорь
задаёт `id` секции, по которому на неё можно сослаться: `/#projects`.

Пустой заголовок означает, что шапка секции не выводится.

## Данные в админке

### Профиль разработчика

Одна запись. Заполняется первой: имя, псевдоним, специализация, краткое и
расширенное описание, фото, локация, доступность к работе, публичный email,
ссылка на резюме.

Краткое описание используется в Hero, расширенное — в блоке «Обо мне» и на
странице `/about/`.

### Настройки сайта

Одна запись: название сайта, подзаголовок, SEO-значения по умолчанию,
изображение для соцсетей, текст в подвале, дополнительные строки `robots.txt`,
коды подтверждения Яндекса и Google.

SEO по умолчанию подставляется там, где у страницы или объекта нет
собственного title и description.

### Навыки

Сначала категория (например, «Языки», «DevOps»), затем навыки внутри неё.

- **порядок** — сортировка внутри категории, меньше значит выше;
- **уровень** — свободный текст, например «продакшн» или «базовый»;
- **показывать на главной** — попадание в блок «Сетка избранных навыков».

Навык нельзя завести дважды в одной категории — это запрещено на уровне базы.
Одноимённый навык в другой категории допустим.

### Проекты

| Поле | Комментарий |
|------|-------------|
| Название, slug | slug формируется из названия и попадает в публичный адрес |
| Короткое описание | выводится в карточке и в мета-описании |
| Полное описание | текст на странице проекта |
| Обложка и alt-текст | alt обязателен для доступности и SEO |
| Категория | используется фильтром каталога и подбором похожих проектов |
| Технологии | связь с навыками; отдельный список технологий не ведётся |
| Ссылки | репозиторий и демонстрация |
| Источник | GitHub, GitVerse или другое — подпись на кнопке репозитория |
| Статус | в разработке, завершён, архив |
| Даты | дата завершения не может быть раньше даты начала |
| Избранный | попадание в блок «Избранные проекты» |
| Опубликован | снятая отметка убирает проект из каталога, из блоков и из sitemap |
| SEO title, SEO description | переопределяют значения по умолчанию |

**Slug не меняется автоматически.** Если изменить его у опубликованного
проекта, старый адрес перестанет работать — настройте перенаправление или
оставьте slug прежним.

Массовые действия доступны прямо в списке: отметки «избранный», «опубликован» и
порядок редактируются без открытия карточки.

### Мини-проекты

Небольшие браузерные инструменты. Ведут на внешний адрес, отдельной страницы на
сайте не имеют. Отметка «активен» скрывает инструмент, не удаляя его.

### Опыт и образование

Записи выводятся на `/resume/` и в соответствующих блоках.

Ограничения базы:

- дата окончания не раньше даты начала;
- у текущего места работы дата окончания должна быть пустой.

### Статьи

Черновик виден только в админке: он не отображается в списке, недоступен по
прямой ссылке (отдаёт 404) и не попадает в sitemap.

Публикация — статус «Опубликована» плюс дата публикации. Дата в будущем
работает как отложенная публикация: до её наступления статья остаётся скрытой.

Массовые действия «Опубликовать выбранные статьи» и «Снять с публикации»
доступны в списке.

Время чтения считается автоматически, если поле оставлено нулём.

### Социальные ссылки

Выводятся в подвале, в контактном блоке и в структурированных данных
Schema.org. Отметка «отображать» скрывает ссылку, не удаляя её.

### Обращения

Сообщения из контактной формы. Создать обращение вручную нельзя — только через
публичную форму.

Текст обращения и технические данные (IP, User-Agent) не показываются в списке
и открываются только в карточке. Уведомление на почту содержит имя и адрес
отправителя, но не текст сообщения — читать его следует в админке.

Обработанные обращения отмечаются массовым действием.

## Изображения

- **Обложка проекта и статьи** — 1200×630 px, соотношение 16:9;
- **Фото профиля** — квадрат, от 320×320 px;
- **Изображение для соцсетей** — 1200×630 px.

Заполняйте alt-текст: он нужен и для доступности, и для поиска. Если alt пуст,
подставляется название объекта.

Изображения на страницах загружаются лениво и имеют заданные размеры, поэтому
вёрстка не «прыгает» при загрузке.

## SEO

Автоматически формируются:

- `title` и `description` с подстановкой значений по умолчанию;
- canonical URL;
- Open Graph и Twitter Card;
- `sitemap.xml` — без черновиков и неопубликованных объектов;
- `robots.txt`;
- структурированные данные: `Person` и `WebSite` на всех страницах,
  `BlogPosting` на статье, `SoftwareSourceCode` на проекте.

Что зависит от редактора:

- осмысленные slug;
- заполненные SEO title и SEO description у важных страниц;
- alt-тексты;
- один заголовок первого уровня на странице — он формируется шаблоном, поэтому
  не добавляйте `<h1>` в текстовых блоках.

## Английская версия

Инфраструктура готова: язык `en` объявлен в настройках, интерфейсные подписи
подготовлены к переводу, адреса будут вида `/en/...`.

Чтобы включить версию, потребуется:

1. перевести интерфейс (`makemessages` → перевод → `compilemessages`);
2. создать англоязычные варианты страниц в дереве CMS;
3. решить, как переводить содержимое моделей — сейчас проекты и статьи хранятся
   в одном языке.

Пока английские страницы не созданы, посетитель видит русскую версию.

## Частые задачи

**Поменять порядок блоков на главной**
Режим **Structure** → перетащите блок внутри плейсхолдера → опубликуйте.

**Убрать проект с сайта, не удаляя его**
Снимите отметку «опубликован». Проект исчезнет из каталога, из блоков и из
sitemap.

**Показать другой набор проектов на главной**
Откройте блок «Избранные проекты» и укажите категорию, или отметьте нужные
проекты как избранные в админке.

**Временно скрыть контактную форму**
В контактном блоке снимите «показывать форму». Страница `/contacts/` при этом
продолжит работать.

**Добавить строку в robots.txt**
Настройки сайта → «дополнительные строки robots.txt».
